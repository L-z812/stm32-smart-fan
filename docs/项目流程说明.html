STM32F103C8T6 · Keil MDK · 标准外设库

旋钮控速电机 · 项目流程总览

01先把角色分工搞清

整个项目只有三类角色。看懂这张图，代码就只剩"翻译"工作了。

图 1　系统框图：两个输入、一个大脑、四个输出

先记住这句 代码里所有叫 Voltage 的东西，其实都是"温度（0~100℃）"。 名字起错了，但公式 100-(ADValue-1730)/2.1 干的事就是把 1730~1940 的 ADC 值线性拉成 0~100。 把这个概念换过来，代码立刻顺了。

03工程目录地图：哪些是别人的，哪些是你的

7 个文件夹里只有 3 个半需要读，其余是"库"，当黑盒用。

目录性质内容要读吗
Start\ST 官方启动文件 startup_stm32f10x_md.s、stm32f10x.h（63 万字节的寄存器定义）、system_stm32f10x.c（配 72 MHz 时钟）不用读
Library\ST 官方标准外设库：GPIO / TIM / ADC / EXTI / RCC… 全部外设的底层函数查函数时看
System\模板Delay.c：用 SysTick 做 us / ms 延时扫一眼
Hardware\你的驱动AD、Motor、PWM、Encoder、Key、LED、OLED、Timer —— 8 个模块必读
User\你的逻辑main.c（81 行，全部业务逻辑都在这）+ stm32f10x_it.c（中断模板，空的）必读
Objects\编译产物Project.axf（可下载）、.o/.d/.crf、Project.build_log.htm不用读
Listings\编译产物Project.map（内存分布）、启动文件汇编清单查内存时看

推荐的阅读顺序（30 分钟能通）

  1. main.c（81 行）——先看 while(1)，这是整个项目的"剧本"。
  2. Motor.c / PWM.c ——搞清"速度"最后变成了什么电平：方向脚 + CCR 比较值。
  3. AD.c ——搞清 ADC 是软件触发的单次转换，转换完才返回。
  4. Encoder.c ——搞清"增量"是中断里加出来的，Encoder_Get() 读一次就清零。
  5. Timer.c ——搞清 1 kHz 中断在干嘛（蜂鸣器方波）。
  6. OLED.c / Key.c / LED.c ——可以跳过，但要知道 Key 和 LED 是"死代码"。
小发现 压缩包里那段 2 分 12 秒的演示视频（d171f5affa45b8fe2b62e1e75b380575.mp4）录的是同一套硬件； 但如果拿视频里的 Speed/Voltage 数值和现在的代码对，会发现对不上——录视频时多半是更早的一版程序。以代码为准。

04上电初始化流程

复位后先跑启动文件，再进 main()，按 main.c:18-23 的顺序初始化 6 个模块。

顺序调用占用的资源具体做了什么
1OLED_Init()PB8、PB9
（顺带 PB12）		把 PB8/PB9 配成开漏输出，发 SSD1306 初始化命令。注意 OLED.c:16 写的是 Pin_8|Pin_12，把蜂鸣器脚也配了。
2Motor_Init()PA4/PA5/PA8/PA9方向脚 + 两个灯配成推挽输出；末尾调用 PWM_Init()。
2.1PWM_Init()TIM2 + PA2ARR=99，PSC=35 → 20 kHz、100 级分辨率的 PWM，开 CH3。
3Key_Init()PB1、PB11上拉输入。PB1 和旋钮 B 相撞了。
4Encoder_Init()PB0/PB1 + EXTI0/1两相下拉输入、下降沿中断、NVIC 分组 2，抢占优先级 1。
5Timer_Init()TIM2（又是它）ARR=9，PSC=71 → 1 kHz 更新中断。这一步把第 2.1 步的 PWM 时基覆盖掉了。
6AD_Init()PA0 + ADC1ADCCLK=12 MHz，单次、非扫描、右对齐，执行 RSTCAL → CAL 校准。
关键：第 5 步把第 2.1 步的 PWM 时基改了 TIM_TimeBaseInit(TIM2, …) 会直接重写 ARR 和 PSC。 PWM 的周期从 99 变成 9，也就是占空比只剩 0~9 共 10 个等级； 只要速度 ≥ 10，CCR 就大于 ARR，输出恒为高 → 实际是 100% 满速； PWM 频率也从 20 kHz 变成 100 kHz（多数驱动模块跟不上）。详见第 09 节第 1 条。

05主循环流程（核心）

这 30 行是整个项目的全部"大脑"。看懂这张图，项目就通了八成。

图 2　主循环流程：一次循环约几毫秒，然后回到 ①

和代码逐行对照

while (1)                                    // main.c:28
{
    ADValue = AD_GetValue();             // main.c:30  采样一次 PA0（阻塞等 EOC）
    Voltage = 100-((ADValue-1730)/2.1);  // main.c:31  ADC → 温度 0~100
    KeyNum  = Key_GetNum();              // main.c:32  没用，还会卡主循环

    if(Voltage>25){                      // main.c:33  自动档
        if(Voltage>65){                   // main.c:34  超温报警
            flag=1;                       //            打开蜂鸣器
            PA8=低(红灯亮); PA9=高;        // main.c:37-38
        }
        if(55<Voltage<65) 两灯都灭;      // main.c:40  预警带
        if(Voltage<55){ flag=0; 红灯灭; 绿灯亮; }  // main.c:41-46
        Speed=Voltage;                    // main.c:47  温度直接当速度
        if(Voltage>=100) Speed=99;        // main.c:48  边界
    }
    if(Voltage<=25 && Voltage>=20) Speed=0;   // main.c:50  死区
    if(Voltage<20) Speed += 4*Encoder_Get(); // main.c:51-53 手动档

    if(Speed>=100 || Speed<=-100) Speed=0;   // main.c:54  限幅

    Motor_SetSpeed(Speed);               // main.c:55
    OLED_ShowSignedNum(2,7,Speed,3);     // main.c:56
    OLED_ShowNum(3,9,Voltage,3);         // main.c:57  小数被截断
}
三个模式是互斥的，但写法上用了三个独立 if 因为条件是 >25 / 20~25 / <20 三段互不重叠，所以结果正确； 但读的时候容易误以为会同时执行。如果改成 if / else if / else，可读性和执行效率都会更好。

06三种工作模式 + 报警子状态

模式切换只由一个变量决定：温度 T。这就是一个最简单的"状态机"。

图 3　模式状态机：三档互斥，报警是自动档里的子状态

温度 T电机红灯 PA8绿灯 PA9蜂鸣器
T < 20℃旋钮手动调速灭（高）亮（低）静音
20 ≤ T ≤ 25℃停转（速度 0）灭（高）亮（低）静音
25 < T ≤ 55℃速度 = T灭（高）亮（低）静音
55 < T ≤ 65℃速度 = T灭（高）灭（高）静音
T > 65℃速度 = T（但受 PWM 坑影响）亮（低）灭（高）响
注意"亮"和"灭"是反的 两个灯都是低电平点亮（GPIO_ResetBits 才是亮）。 唯独 55~65℃ 这一段"两个都置高"，所以看起来是"两个都灭"——这是作者的刻意设计（预警=无灯），不是笔误。

07中断都在干什么

一共 3 个中断：两个数旋钮，一个发蜂鸣器方波。中断里千万不能放延时和死循环。

① 旋钮计数（EXTI0 / EXTI1）

// Encoder.c:82-98   PB0 下降沿
void EXTI0_IRQHandler(void)
{
  if(EXTI_GetITStatus(EXTI_Line0)==SET){
    if(PB0==0 && PB1==0)   // 看另一相判断方向
        Encoder_Count--;    // 反转
    EXTI_ClearITPendingBit(EXTI_Line0);
  }
}

PB1 下降沿则 Encoder_Count++（Encoder.c:108-124）。 主循环用 Encoder_Get() 取走增量并清零，所以叫"增量"而不是"位置"。

② 蜂鸣器发声（TIM2 更新中断）

// main.c:60-81    1 kHz 进一次
void TIM2_IRQHandler(void)
{
  i++;
  if(flag==1){
    TIM_SetAutoreload(TIM2,190);  // 改频率=改音调
    if(i%2==0) PB12=1;  else PB12=0;  // 方波
  }
  if(flag==0){ PB12=1; 还原两个灯; }
  TIM_ClearITPendingBit(TIM2, TIM_IT_Update);
}

靠"每进一次中断翻转一次引脚"造方波： 72 MHz ÷ 72 ÷ 191 ÷ 2 ≈ 2.6 kHz，人耳听得到的高音。

致命点：这个中断和 PWM 抢的是同一个定时器 TIM2 既要输出 PWM（CH3），又要产生更新中断来发蜂鸣器。 main.c:66 里的 TIM_SetAutoreload(TIM2,190) 改的是同一个 ARR， 所以每次报警，PWM 的周期和占空比都会被顺手改掉，而且 flag 回到 0 时没有还原 ARR。

09你可能被绕晕的 8 个坑

"代码看着都对，但现象不对劲"——原因基本都在这里。前三条是真的会影响功能。

严重1. TIM2 被配置了两次，PWM 只剩 10 级

现象速度显示 20、50、90，风扇转速看起来几乎一样快，旋钮低速区才有一点变化。

原因Motor_Init() 里 PWM_Init() 先设 ARR=99, PSC=35（PWM.c:29-30）， 紧接着 Timer_Init() 又把 同一个 TIM2 设成 ARR=9, PSC=71（Timer.c:20-21）。

后果占空比公式变成 CCR/(ARR+1) = CCR/10：只要 CCR ≥ 10 就是恒高电平（100%）， PWM 频率也从 20 kHz 变成 100 kHz。

改法蜂鸣器换一个定时器（TIM3 或 TIM4），TIM2 只留给 PWM。

严重2. 报警时改 ARR，而且永不还原

原因main.c:66 的 TIM_SetAutoreload(TIM2,190) 改的就是 PWM 的周期寄存器， flag 变回 0 时没有任何地方把它改回 9。

后果报过一次警之后，占空比永久变成 CCR/191（99 只能得到 52%）， 中断频率也从 1 kHz 变成 5.2 kHz——电机明显变弱，蜂鸣器音调也跟着变。

改法同第 1 条；若一定要改 ARR，要在 flag==0 分支里改回去。

严重3. PB1 一脚两用：旋钮 B 相 + 按键 1

原因Key.c:17 把 PB1 当按键，Key_GetNum() 在 main.c:32 每圈都调用； 读到低电平就 Delay_ms(20)，然后 while(PB1==0);（Key.c:35）死等。

后果转旋钮时主循环被卡住几十毫秒，OLED 闪烁、调速发滞； 如果旋钮正好停在 B 相为低的位置，程序会永远卡在那里，电机保持上一次的速度。

改法删掉 main.c:32 这一行和 Key 模块（项目根本没用按键）。

中等4. LED.c 是死代码，还和 PWM 抢 PA2

LED_Init() 把 PA1、PA2 配成推挽输出（LED.c:16），可 PA2 是 PWM 输出脚。 好在 LED_Init() 从没被调用，所以没炸。真正的红绿灯是在 Motor.c:16 里顺手初始化的 PA8/PA9。

建议把 LED.c/LED.h 移出工程，或者改成 PA8/PA9 并统一"低电平亮"。

中等5. 蜂鸣器脚 PB12 是"别人帮忙"初始化的

全工程没有任何地方把 PB12 配成输出。它能响，纯粹因为 OLED.c:16 写成了 GPIO_Pin_8|GPIO_Pin_12（多写了个 12），把它配成了开漏输出。

风险谁"顺手清理"一下 OLED.c 这行，蜂鸣器立刻不响，而且查半天查不出来。

建议在蜂鸣器自己的模块里明确初始化 PB12，OLED.c 改回 Pin_8。

中等6. 名字骗人：Voltage 其实是温度

Voltage、AD_Init、"温度变量"三个叫法混在一起，OLED 上还写着 Voltage:。 实际它是 0~100℃ 的温度。改名叫 Temperature 并同步改 OLED 文字，代码可读性立刻上一个台阶。

轻微7. Speed 用 int8_t 表达 −100~100，会溢出

int8_t 的范围是 −128~127，Speed += 4*Encoder_Get()（main.c:52） 在快速拧旋钮时可能直接溢出变成反号。另外 if(Speed>=100||Speed<=-100) Speed=0; 是"清零"而不是"限幅"，拧过头会突然从满速跳到停转，手感很怪。

改法用 int16_t，并改成真正的限幅。

轻微8. 温度没有限幅，负温度会显示成天文数字

ADValue 小于 1730 时 T 会大于 100，大于 1940 时 T 变负数。 OLED_ShowNum 的参数是 uint32_t，负的 float 转过去会变成一个巨大的数。

改法if(T>100) T=100; if(T<0) T=0;，顺便加个 ADC 多次平均。

10建议的修改顺序

按这个顺序改，每一步都能独立验证，不会一次改崩。

  1. 把蜂鸣器从 TIM2 挪到 TIM3（一步解决坑 1、坑 2）
    Timer.c 里 5 处 TIM2 → TIM3（第 11、14、23、42、49 行）， 第 42 行的通道改成 TIM3_IRQn；main.c 的中断函数改名为 TIM3_IRQHandler，函数体里的 TIM2 一并替换。
  2. 删掉多余的按键扫描
    删 main.c:32 的 KeyNum = Key_GetNum();（可连同 Key_Init() 一起删）。PB1 从此只属于编码器。
  3. 变量改名 + 真限幅（解决坑 6、7、8） 
    int16_t Temperature, Speed;   // 不再用 float 和 int8_t

ADValue    = AD_GetValue();
Temperature = 100 - (int16_t)((ADValue - 1730) / 2.1f);
if (Temperature > 100) Temperature = 100;   // 限幅，别让负温度跑出去
if (Temperature < 0)   Temperature = 0;

// 原来的 "超过就清零" 换成真正的限幅
if (Speed > 100)  Speed = 100;
if (Speed < -100) Speed = -100;
  4. 把 Motor_SetSpeed 的参数也改成 int16_t，避免调用处隐式截断。
  5. 清理死代码：从 Keil 工程里移除 LED.c；OLED.c:16 改回 GPIO_Pin_8； 在 main 里显式把 PB12 配成推挽输出。
  6. 加一点滤波：连续采 8 次 ADC 求平均再换算，温度读数就不会个位数乱跳。 
    uint32_t sum = 0;
for (uint8_t n = 0; n < 8; n++) sum += AD_GetValue();
ADValue = sum / 8;
  7. 最后再动结构：把 main 里的三档判断抽成 Motor_Task(void)， 主循环只剩三行：采样、决策、显示。这样"流程"才真的清晰。
改完预期 风扇能真正按 0~100 级调速；报警时音调正常、电机不掉速；转旋钮不再卡顿； OLED 上的数字和实际转速对得上。

1230 秒讲清这个项目

答辩时照着念就行 这是一个基于 STM32F103C8T6 的智能降温风扇。
感知：PA0 接温度传感器，ADC1 每轮采一次，把 1730~1940 的 ADC 值线性换算成 0~100℃。
决策：主循环按温度分三档——高于 25℃ 自动按温度定速（温度越高转得越快）； 20~25℃ 是死区，直接停机；低于 20℃ 交给旋钮手动调速。
执行：速度经 PA4/PA5 定方向，PA2 用 TIM2_CH3 输出 PWM 控制占空比。
交互：旋钮接 PB0/PB1，两路外部中断数脉冲得到增量； 55~65℃ 两灯灭作预警，超过 65℃ 红灯亮、蜂鸣器响，回落到 55℃ 才解除（迟滞 10℃）。
显示：OLED 用 PB8/PB9 软件 I²C，实时显示速度和温度。

如果老师追问"为什么要死区"：因为温度在 20℃ 附近抖动时，自动档和手动档会来回切换， 死区就是给这个临界点加的一段缓冲，避免转速突然跳变。
